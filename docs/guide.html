2. Set up Windows

Use PowerShell in the project root: the folder containing Control.cmd and Run.cmd. These steps explicitly install or acquire dependencies. Opening the website or Control does not install them.

  1. Install the platform tools. You need Git, Windows Python 3.10+, Juliaup, WSL2 with Ubuntu-24.04, and Pixi inside Ubuntu. Follow the official Juliaup, WSL and Pixi instructions. WSL may need an administrator and restart. No GPU or ParaView installation is required.
  2. Extract the student software. Use the verified software ZIP above, and keep its extracted folder in its final location. It includes the Control runtime, canonical detector models, pinned environment files and this guide. Saved results, standalone demonstrations, developer tests, reports, publication tools, Git history and installed dependencies are excluded. Browse existing results online. Software-only Control shows original model settings and links to the online geometry viewer when a local saved preview is unavailable.
  3. Prepare the pinned Julia environment. 
    juliaup add 1.13.0
juliaup override set 1.13.0
julia --version
julia --startup-file=no --project=simulation -e "using Pkg; Pkg.instantiate()"

    The directory override selects Julia 1.13.0 for this checkout. Keep the supplied Project/Manifest pair unchanged; it pins SSD 0.11.8, JSON 1.9.0 and Unitful 1.29.0.

  4. Install the locked Linux transport environment. 
    $Project = (Get-Location).Path
wsl.exe -d Ubuntu-24.04 --cd "$Project\transport" -- bash -lc '$HOME/.pixi/bin/pixi install --locked'
.\transport\Run.cmd versions

    The version check should report remage 1.1.0 and Geant4 11.3.2. Pixi keeps the large environment in its Linux cache.

  5. Acquire the exact upstream cryostat files. Expand the recipe below. The nine files are fetched locally from the manifest-pinned commit and verified before use.
    Download the nine pinned source files

    The authority is transport/cryostat-source.json: jintonic/geant4, commit 1ff3371e0afb804115773af0541b3e56bd660f8c, directory detector/Ge/cryostat/LBNL. Run this in the project root:

    $m = Get-Content .\transport\cryostat-source.json -Raw | ConvertFrom-Json
$target = Join-Path (Get-Location).Path $m.local_cache
New-Item -ItemType Directory -Force $target | Out-Null
foreach ($f in $m.files) {
    $dest = Join-Path $target $f.name
    if (Test-Path -LiteralPath $dest) {
        if ((Get-FileHash -LiteralPath $dest).Hash.ToLowerInvariant() -ne $f.sha256) { throw "Existing file differs: $($f.name)" }
        continue
    }
    $temp = $dest + '.download'
    if (Test-Path -LiteralPath $temp) { throw "Inspect previous download first: $temp" }
    $url = 'https://raw.githubusercontent.com/' + $m.repository + '/' + $m.commit + '/' + $m.directory + '/' + $f.name
    Invoke-WebRequest -UseBasicParsing -Uri $url -OutFile $temp
    if ((Get-Item -LiteralPath $temp).Length -ne $f.bytes -or (Get-FileHash -LiteralPath $temp).Hash.ToLowerInvariant() -ne $f.sha256) { throw "Downloaded bytes differ: $($f.name)" }
    [IO.File]::Move($temp, $dest)
}

    Matching existing files are preserved. A failed attempt leaves its labelled .download file for inspection. The final files belong directly in .local/transport/LBNL/. They are not republished or relicensed by this project.

  6. Build the source-bound exporter used by Control. 
    .\Run.cmd setup -BuildPortableSourceExporter
.\Run.cmd setup -BuildCatalogSourceExporter
.\Run.cmd setup -BuildAngleSourceExporter
.\Control.cmd

    These explicit builds use the existing locked environment and record the exporter/source bindings. The first preserves the original five-model route; the second builds the shared geometry exporter for the additional compatible models; the third adds angular geometry support. They install or update no packages. In Control, Check environment reports file readiness. Select a setup and use Check plan to verify its current build, source, runtime and settings. Address any missing or changed dependency before running. Control opens a protected local page on 127.0.0.1.

Setup checkpoint: Control opens Local simulation in your browser. Check environment lists the prepared dependencies; finish any missing item before continuing to the first SAP22 run.

The application and source-bound preparation have been verified on the existing Windows/WSL computer. Fresh-machine installation has not been established; student setup feedback will guide further fixes. A failed prerequisite check is not a successful installation.

Select an existing Python or Julia executable

Control uses SITE_PYTHON when set, otherwise an existing ParaView 6.1.1 Python, otherwise an existing PATH Python. To select an already installed interpreter for this PowerShell session:

$env:SITE_PYTHON = 'C:\path\to\installed\python.exe'
.\Control.cmd

Replace the illustrative path with the actual executable. The child workflow uses the pinned Julia runtime; an explicit JULIA_EXE must be valid. Opening Control installs nothing and does not change system PATH.

  1. Prepare the three platform tools once. Install Juliaup and Pixi (0.81.0 or newer). Install Apple's Command Line Tools by running xcode-select --install in Terminal and completing Apple's installer. Use a native terminal for your Mac's processor. The dependency lock targets macOS 13 or newer.
  2. Extract the software and run Setup.command. Setup installs the pinned Julia 1.13.0 CPU environment and the locked Mac transport environment, fetches the nine hash-checked cryostat source files, and builds the geometry exporters. First setup includes downloading and compiling dependencies; later launches reuse them. Keep the extracted folder in its final location. Setup does not run a simulation. Its progress and any failure remain available for diagnosis.
  3. Open Control.command. Keep its terminal window open while using the local application in your browser. The Local simulation page is the setup checkpoint. Continue with the first SAP22 run; the same Stop/Resume controls apply on both systems.

If a launcher opens as text, open Terminal in the extracted folder and run bash Setup.command or bash Control.command. Opening Control uses the prepared environment; it installs nothing.

Native macOS 15 installation, CPU calculation and stage stop/resume have been checked with a 100-initial-event SAP22/Cs137 case. Its preserved Mac data were also checked through the production Control result reader on Windows. See the Apple Silicon and Intel test records for each platform's status and exact scope. This is a functional software check; detector accuracy and model-specific limits remain separate.

3. Complete one small run

Open Control.cmd on Windows or Control.command on macOS in the project root. It opens the English Local simulation application. New runs calculate geometry/source preparation, radiation deposits, the event ledger, fields and charge, independent calibration, readout, and verified results.

First run: SAP22 · Cs-137 · 100 initial decays

Use the configuration from the completed native macOS and preserved Windows result-reader checks: LBNL modular cryostat, SAP22, Cs137 point decay, nominal source anchor, source/capsule angle +30°, 100 initial nuclei, radiation seed 26092631, one Julia thread and unchanged default electronics. Use a new name such as sap22-first. This is a bounded software example; its saved acceptance contained 97 zero-deposit primaries and three accepted groups, while a changed configuration or seed may give different counts.

  1. Choose the configuration above and inspect the SAP22 model panel. Enter the new unused run name.
  2. Keep Electronics settings at their defaults for this first run. Use Export configuration to save the exact setup.
  3. Click Check plan. Review the effective position/orientation in Checked source pose and the Checked next-run configuration. Changing any selection, including angle, invalidates the check.
  4. Click Run simulation. Follow Pipeline and open the stage logs from Runs.
  5. Choose Explore events after completion, or at a stopped boundary with completed batches. Find the matching files and event filters under Saved stage files, below the signal plots. The selected saved run stays separate from the next-run form.

Open it → Explore events → select a nonzero original primary and pulse group → compare charge and readout plots. Saved stage files, below the plots, opens the settings and actual ledgers. For sap22-first, the output folder is .local/runs/sap22-first/. Keep any recorded failures distinct from accepted groups.

After the first run: choose other settings

Select another supported detector, cryostat, source, source/capsule angle, primary count or thread count. 5. Stop, resume and adjust settings

For a decay run, choose Stop at next boundary in the run card. The current stage or batch reaches a verified completed boundary first; Stop is not immediate. When the status is Stopped at stage boundary, Resume saved settings verifies sealed stages and batches, reuses completed work and continues pending work with the same settings. Completed batches remain available through Explore events. Keep the launcher open until completion or the stopped boundary. Uncertain unsealed attempts are retained for inspection and refused rather than silently rerun. The legacy gamma route uses Stop after current stage. See the shared count and recovery contract.

To change detector, source or electronics, export or edit a configuration and choose a new unused run name. Resume always uses the stopped run’s saved settings. The fresh two-source GeGI acquisition has its own Stop and Resume saved acquisition controls, preserving its continuous source and electronics state.

6. Analyze your own results

Use Show stages for that run's settings, receipts and logs; use Explore events for its original primary IDs and pulse groups. A saved nonzero waveform is selected first when available. The charge, original-bin current, analog preamp and analog shaper plots retain their signed signals and units.

Each signal has a useful independent focus range; Full saved window restores its saved time span. Where a dense early preamp view is available, it is an explicitly labelled electronics-only replay from full signed charge. It does not recover unsaved original analog samples or alter the original peak, ADC code or reconstructed energy. Collection caps and incomplete endpoints remain visible.

Truth deposited energy, induced charge-equivalent energy and reconstructed energy are separate values. A true zero has no fabricated waveform and keeps reconstructed energy unavailable. Native failures retain their truth and error; unknown response quantities remain null. Changing the next-run form does not relabel the saved result. Selected run source pose and Selected run settings show that run's recorded angle, position, rotation and provenance; earlier runs remain labelled as legacy fixed poses. Stop/Resume uses those saved settings.

For a batch run, select its zero-based Saved batch index and Nonzero event offset, then use Load saved page, Previous page or Next page. Pages load on demand and list only nonzero-deposit events with their original IDs. The offset counts stored nonzero events, not the original primary ID. Initial, zero/nonzero, failed and rejected totals remain in the summary, with the original efficiency denominator. New normalized truth/scalars and analysis JSON/CSV omit zero-input rows and artificial zero waveforms; nonzero failures and rejections stay. Historical raw files remain unchanged. Waveform previews cover only the first 16 groups per batch; other groups retain their saved scalar results and full native signals, with preview unavailability shown explicitly.

Saved energy spectrum · raw counts reads an existing verified histogram. Its label distinguishes the full run from the selected sealed batch; it does not use only the current event page. Truth deposited energy per initial primary and accepted peak-ADC reconstructed energy per pulse remain separate populations. The original initial/zero/nonzero census and underflow/overflow counts remain explicit; this is not an experimental spectrum or physical-resolution claim. Waveform feature and synthetic acquisition panels appear only when their saved export is present, and opening them still verifies their inputs without starting a calculation or export.

7. Troubleshoot a setup or run

  • Setup fails: keep its log and exact error, then check the platform prerequisites and pinned versions above. Opening Control does not install dependencies.
  • Check plan refuses the setup: inspect the stated compatibility, source pose or missing input. Check again after any change.
  • No energy or waveform: check the initial/nonzero counts, native-failure status, threshold and saved-waveform coverage. An unavailable response is not zero.
  • A run was interrupted: inspect its saved completion state before another launch. Use Resume saved settings at a verified stopped boundary or the specifically supported recovery tools.

For GitHub Issues, include the operating system, software revision, detector/source/count, run name, failing step and exact error.

What the examples establish

The five original Control connectors retain their completed bounded examples. Each of the five added models completed one preselected 500-decay Cs137 case through the public Check, Run and Inspect commands on the existing prepared computer. All 2,500 initial events remain: 2,485 zero-deposit events and 15 pulse groups, comprising nine accepted groups, three below-threshold readout rejections and three KL01 native failures. The KL01 failures keep their original truth and error with unknown charge/readout null; they are not successful charge calculations. Cs137, Am241 and Ba133 share factorized software support across ten configurations; this does not mean thirty actual model/source science acceptances.

These are bounded engineering examples with synthetic electronics and explicit model/geometry limitations. Successful processing does not establish calibrated charge-collection efficiency, experimental agreement, physical energy resolution or numerical convergence.

Source creation/deposition time is not carrier drift time. A readout threshold changes acceptance, not the original primary census. Zeros, endpoint/cap flags, electronics rejects and native failures remain distinct. The GeRC02 Li50min operating variant and KM candidate keep their recorded model and polarity qualifications.

Platform setup and test scope are recorded in the installation sections above. Saved galleries, 10K campaigns and million-decay radiation results are distinct datasets; follow each page's scope and receipts.

Configuration topics

GeGI: source, 34 electrodes and Compton imaging

Rotate the GeGI cryostat and inspect its dimensions · GeGI detector model · Four independent acquisitions: signals and conditional imaging. The public results and your own local runs retain separate input settings and event identities.

  1. Choose the setup. Open Control, select GeGI cryostat and GeGI, then choose its monoenergetic gamma point source. Enter gamma energy from 1 to 10000 keV, source x/y/z in mm and 1–10000 initial gamma primaries. The crystal centre is the origin and +z is the front. This source is isotropic: the denominator counts every emitted gamma, including misses. Start with 100; a small run can have no Ge deposit.
  2. Check and run. Set electronics, a radiation seed and one or two Julia threads, then choose Check plan. Inspect the resolved settings and choose Run to execute geometry, transport, event ledger, native charge, independent calibration, readout and reconstruction in one workflow. Stop waits for a stage boundary; Resume reuses verified completed work with the saved settings. The first installation computes native fields; an exact locally saved GeGI state can be reused. Field data and precomputed examples are not included in the software ZIP.
  3. Follow your event. Open the completed run and select an original nonzero primary ID. The event journey shows actual signed charge, current, preamp and shaper samples for all 32 strips and two guards, plus the shared waveform-reconstruction status. New standalone runs do not infer depth or create a source map without a compatible independent waveform calibration. Fixed energy readout and original timing diagnostics remain available. Open the event identity and stage-file panels for the exact native JSON/CSV, original LH5 transport, ledger, independent electronics calibration, configuration and recorded hashes under .local/runs/NAME/.

The standalone transport workflow launches a monoenergetic gamma source. To generate new Cs-137 and Co-60 decays together, use fresh sources with compact candidate storage. For historical shared-readout diagnostics, replay two saved decay libraries with their original geometries and daughter delays.

The measured front stack has a 1.6 mm exterior cover, 0.8 mm inner shield and an 8.1 mm crystal-to-exterior-front distance. The missing side/rear dimensions and vacuum-gap split are explicit engineering approximations; both specified aluminium alloys use pure aluminium in this first transport model. The frozen 92.3 K, −879/0 V semiconductor model and its original assumptions are unchanged.

X and Y each measure the same deposited charge and must not be added together as event energy. Fixed family wiring and independent injection calibration convert signed signals to readout energies. Failed or rejected nonzero events remain selectable; unavailable signal quantities remain null. Initial, zero-deposit, nonzero, failed and rejected counts retain the original efficiency denominator. Charge timing uses the saved analog numerical grid; a deposition time is not a drift time, and the peak ADC is not a digitized hardware waveform.

Older saved GeGI runs use the historical terminal-charge CFD (constant-fraction discrimination) timing and strict two-by-two strip pairing, with central-pixel or explicitly supplied per-pixel timing tables. Those maps remain experimental legacy results. A displayed cone or two visible map peaks does not establish correct interaction depths or source locations. The separate Transport truth · evaluation only panel contains original radiation deposits; those positions and source coordinates do not choose signal-derived candidates.

Reprocess a completed GeGI campaign without new simulation

Control’s Reprocess saved GeGI signals panel accepts the completed campaign format with sealed events.sqlite stores and chunk DONE.json receipts. This is a different format from a standalone Control run’s response/results.json. Imported campaign directories belong under .local/gegi-saved-inputs/campaigns/NAME/; independent saved template directories belong under .local/gegi-saved-inputs/calibrations/NAME/. Existing project dataset/campaign directories and immediate saved calibration siblings are also listed. No campaign, template bank or demonstration is bundled in the student ZIP.

  1. Click Refresh saved inputs, choose a completed sealed campaign and, when available, its compatible independent saved templates. With no compatible templates, depth remains unsupported.
  2. Enter a new derivative name and click Reprocess saved signals. The action reads the original SQLite stores in read-only mode and checks the original seals and signal hashes. It runs the same gegi_saved_reconstruction.py entry used from the command line; it starts no radiation, native drift, field solve or calibration injection.
  3. Follow the original pulse-group totals, conditional-candidate counts and status. Stop after current chunk preserves completed chunks. Resume selected derivative keeps the same saved inputs, calibration and implementation identity; incomplete unsealed output requires inspection.
  4. Open the identity, progress, summary and completion records in Control. Actual compressed event derivatives remain in .local/gegi-saved-reconstruction/NAME/chunks/, with original primary/pulse-group IDs. Original initial/zero/nonzero/failure counts remain in the summary; no zero waveform is created.

The shared saved-signal algorithm preserves all 34 signed electrode observations and conditional pairing/order ambiguity. Independent saved injection responses provide an approximate modeled response where supported. The existing calibration is not a complete independently validated 34-channel response bank: unsupported channels, absent templates or ambiguous residuals can leave few or no supported three-dimensional hypotheses. Conditional candidates are not validated recovered events. No measured depth, energy or angular-resolution validation, recovered range or source activity is implied.

Read the result by use: spectroscopy retains the original fixed-gain readout energy; an ambiguous imaging hypothesis keeps competing strip pairings and photon sequences. Failed or incomplete groups keep unknown quantities. A guard transient is different from terminal guard collection, and signal-feature totals can overlap. The four independent acquisitions publish Selection, uncertainty and saved evidence, including the original denominators and a same-event evaluation subset of 153 groups / 287 candidate orders; 550 other candidate orders remain unevaluated. These public files do not provide the development/holdout error tables or small-sample peak-stability check previously described for this study. The 1 ns signal grid is numerical integration, not a verified hardware waveform sampling rate.

Run fresh GeGI sources with compact candidate storage

In Control, open Run GeGI with two fresh sources. Set the Cs-137 and Co-60 positions and activities, choose Steady source · physical duration, enter a positive finite duration in seconds (default 5 seconds), and choose a new acquisition name. Duration follows the detector's acquisition clock and has no fixed software ceiling. New parent decays arrive randomly at the selected activities; their realized count is not prescribed. Both sources are defined before transport in one geometry. Their deposits enter one chronological queue; overlapping currents share the same absolute clock, front end, noise, ADC and trigger. Computational blocks retain that clock and electronic state, using the field cache from a completed ordinary GeGI run.

The steady-source choice includes an initial Ba137m daughter inventory from the source equilibrium model, bound to pinned Geant4 decay data. Electronics start quiet with zero signal history. Control displays Physical acquisition time, New parent decays and Initial-daughter decays separately. The report also separates Ge-zero and Ge-nonzero counts for those two populations and labels any mean initial daughter population as a statistical mean. Physical acquisition duration differs from computational wall time; the run report records final measured wall time and resource use.

For a smaller check, select Startup check · fixed new-parent count and start with the default 100; this mode accepts a configurable positive integer number of new Cs-137/Co-60 parent decays and no pre-existing daughters. In both modes, daughter deposits can occur much later than their parent decay: they wait on disk until the acquisition clock reaches them. Deposits beyond the final recording interval remain identified and counted separately. Only current pulses and local readout history stay in memory; the complete ADC stream is not stored.

Every available signal reaches readout before storage selection. Clean single-pixel triggers contribute to spectra and statistics without retaining waveforms. Multi-strip and ambiguous triggers retain one lossless 34-electrode ADC context, the fast/slow measurements, timing, flags and original trigger IDs. This includes signed signals on noncollecting neighboring strips whose induced charge returns to zero. Finite sampling and ADC resolution still apply. The fast and slow branches can be reproduced from that context; the software does not save three duplicate waveform arrays. A candidate is retained for later analysis and is not automatically a uniquely reconstructed photon.

Click Stop to request a cooperative stop at a durable acquisition boundary; the current operation completes first. Keep Control open until the run is stopped. Choose the same saved acquisition and click Resume saved acquisition to continue with its original settings, identities and pending signals. Editing the next-run form does not change a resumed acquisition. Resource or readout-window bounds stop with preserved evidence rather than silently shortening signals.

Choose a saved acquisition and its original candidate trigger to inspect the preamplifier, fast and slow views. Missing measurements remain unavailable. Results live in .local/gegi-candidate-runs/NAME/: compton-candidates.sqlite holds candidates and compact rejection records; candidate-acquisition.json holds counts, spectra and hashes; compressed identity ledgers retain nonzero parent/group relationships. New temporary transport and native files are retired only after the durable output verifies. Failure evidence and existing scientific originals remain.

Reconstruct a source-plane map: put the separate GeGI calibration in .local/gegi-center-calibration.npz, then refresh the saved acquisitions. Open a completed run and choose External calibration, the assumed plane in detector coordinates, its grid and prior. Click Analyze all two-strip candidates. This reads the saved signals and starts no transport or charge drift. Use Saved source-plane map and Open saved map to reopen a result without fitting it again. Compare the energy windows and their projected and unresolved weights; missing templates and unsupported measurements remain unresolved. A partial analysis is labelled explicitly.

Measured five-second run: one shared acquisition processed 924,676 new Cs-137 parents, 185,199 new Co-60 parents and 867,305 initial daughters. It retained 14,909 candidates, with exact re-extraction of their saved ADC, fast/slow and timing data. The acquisition retained 819 MB; its sampled run-directory peak was 1.02 GB and sampled simultaneous Python/native memory peak was 2.61 GB. It took 6.83 active computing hours on the measured workstation. Use the 100-parent startup mode for an initial software check. All 3,822 two-strip candidates were subsequently processed for imaging in about 230 seconds, using a measured 0.55 GB peak process memory. Missing native response excluded 0.966 seconds of the five-second readout; that loss remains in the counts and time mask.

Storage and time planning: at 185 kBq + 37 kBq, 20 million new parent decays have an expected duration of about 90.09 seconds. The fresh-run measured mix projects roughly 15.8–19.3 GB of retained data, including the field cache and optional reconstruction calibration once, plus saved maps. The acquisition estimate is roughly five active computing days on the measured workstation. These are conditional planning scenarios, not a measured large run or a guaranteed disk maximum: daughter populations and event mix change with exposure, and the upper storage scenario adjusts for unavailable readout history. Temporary database journals and other working files need additional free space. The full continuous ADC stream would be about 306 GB at 34 channels × 50 million samples/s × two bytes/sample; that stream is processed without retaining it in full. Control shows the measured reference and separates acquisition, analysis and shared-cache costs.

Trace a source-plane peak: open a saved map, choose a measured energy window and click Inspect peak contributors. The list gives each original trigger's contribution, strip pairing, scatter order, fitted positions and waveform residual. Open trigger waveforms returns to that exact trigger's saved 34-electrode ADC context. Alternative orders belong to one trigger; their weights are not independent event counts.

Before analyzing, enable Save fit residuals on all 34 electrodes to inspect modeled and unused contacts in the contributor details. For optional substrip coordinates, download the separate lateral calibration overlay (18,083,717 bytes) to .local/gegi-lateral-calibration.npz alongside the center calibration, refresh, and choose Lateral where calibrated. Its six position-tested grids cover only part of the detector. Each fit records which site uses lateral corrections and why any site or pairing remains on center templates. A small residual alone cannot establish that a waveform contains exactly two interactions.

Optional strip-topology diagnostics. From the project root, run python tools/gegi_candidate_topology.py --acquisition .local/gegi-candidate-runs/NAME/candidate-acquisition.json --shared-strip --calibration .local/gegi-center-calibration.npz --trigger-id ID --output .local/gegi-candidate-runs/NAME/topology.json.gz with your run name and original trigger ID. For two strips on each face, use --map PATH with the full saved map in place of --shared-strip. Add --incident-energy-keV ENERGY once per line to compare each measured cell sum with the supplied line and check whether two resolved Compton scatters could leave an escaping photon. These conditional energy checks preserve the original imaging weights and leave merged or mixed interactions unresolved.

Check incident-line kinematics for the whole saved map. Run this from the project root with your run name and one --incident-energy-keV argument per line of interest.

python tools/gegi_candidate_kinematics.py --saved-plane .local/gegi-candidate-runs/NAME/candidate-imaging.json.gz --incident-energy-keV 661.657 --output .local/gegi-candidate-runs/NAME/line-kinematics.json.gz

The compressed ledger keeps every original two-strip trigger and pairing along with its map weights and unresolved outcomes. It reads the scalar measurements from the candidate archive beside the map. For each compatible pairing it records signed energy closure and both two-scatter escape orders, including failed hypotheses. Admissibility can overlap across the supplied lines and does not identify the photon.

New runs also write candidate-truth.jsonl.gz with candidate-linked photon ancestry, scored Ge steps and native endpoints. It is for evaluation and stays separate from signal reconstruction; a context link does not identify which photon caused a trigger. The measured five-second storage projections above predate this artifact and exclude its additional output and staging space. New run reports measure their actual footprint.

Three-dimensional source scoring from the same candidates

Open a saved full candidate map, expand Three-dimensional source range and choose Open saved range analysis to read an existing result. Run 3D range analysis creates a separate result using the displayed search settings. The radial curves, coordinates, distance, original trigger IDs and sensitivity comparisons use the same saved interaction interpretations as the map.

python tools/gegi_candidate_range.py --imaging .local/gegi-candidate-runs/NAME/candidate-imaging.json.gz --output .local/gegi-candidate-runs/NAME/candidate-range.json

This source-blind analysis uses finite interaction vertices and the saved pairing/order mixtures. It fits direction freely and profiles distance from the detector-coordinate origin (0, 0, 0) mm; axial z and center distance are separate outputs. It compares the three line windows, both cobalt lines together, the two acquisition-clock halves and two background assumptions. No source coordinates, known activities or common source plane enter the fit.

Enable background profiling, or add --profile-background to the command, to estimate the extra uniform-angle fraction at every source position. The exact far-field limit is compared using the same event response. A fitted background fraction is a model component, not a measured isotope purity or source activity.

The default numerical search samples 20–10,000 mm with 49 radial points, 192 starting directions and six optimized starts. Use --radius-min-mm, --radius-max-mm, --radial-points, --directions and --starts to compare search convergence. These settings describe the search, not the instrument's range. Open profiles report unidentified distance. Closed profile scores still need independent calibration before they can be treated as confidence intervals. Default strip-position uncertainty and the nominal angular width do not establish measured detector resolution.

The earlier small fresh-source and saved-signal checks retain their stop/resume and continuity evidence. The completed five-second acquisition establishes the working pipeline and its measured resource use; detector accuracy and longer 60–90 second production remain separate claims.

What an acquisition checkpoint preserves

The source checkpoint records the common decay clock, next parent identity and Geant4 random-number state. The candidate database retains future daughter deposits, current pulses, all 34 channel noise-generator states, filter history, unfinished candidate windows, counts and the committed trigger boundary. Resume checks the original configuration and implementation hashes before continuing. Candidate rows and the matching checkpoint commit in one SQLite transaction. The general restart pattern is described by OpenMC batch statepoints; the all-or-nothing database behavior is described in SQLite atomic commit.

The design follows commercial list-mode practice: continuously process signals, record compact measurements and optionally retain pulse traces. XIA describes event headers and optional traces; CAEN separates waveform, list and histogram output. These references explain the storage approach, not GeGI's undocumented internal file sizes or selection rules.

Historical shared-readout replay · two saved GeGI source libraries

This workflow replays two completed GeGI decay libraries through shared readout. It uses their saved radiation and charge signals; to generate new Cs-137 and Co-60 decays together, use the separate fresh-source acquisition with configurable physical duration (default five seconds). The replay libraries must share compatible detector geometry and charge-response calibration. Each retains its isotope, physical source position, original misses and time-resolved electrode signals. To move a source, supply a library simulated at the new position.

  1. Copy each sealed campaign chunk into its own folder under .local/gegi-saved-inputs/source-libraries/. Keep DONE.json, events.sqlite, source-checked.json and the original transport/ files together.
  2. In Control, open Historical readout diagnostic · saved source libraries and refresh. Select both libraries, check their positions in mm and enter each activity in Bq, the exposure in seconds, a random seed and a new result name.
  3. Choose Standard for the default 5 keV-equivalent coincidence threshold per 20 ns sample, or Low energy for 4. Both use the same 3 keV-equivalent quiet threshold per sample and the same energy qualification. These settings describe the nominal simulated digitizer.
  4. Click Run acquisition. Open its result to view qualified recording time, the combined energy spectrum and the detector hit map. Open Inspect single-pixel trigger measurements and choose a trigger number to see its time, strip readings and any calibrated coordinates. The receipt is .local/gegi-dual-source/NAME/report.json.

Both sources feed one continuous digitizer. A pair of closely spaced deposits can produce one trigger, and some triggers have no usable energy. Each qualified trigger with a measured total contributes one entry to the spectrum. The receipt records time excluded because a saved charge response or its electronic tail was uncertain.

To open an existing dual-source report on another installation, copy it to .local/gegi-dual-source/NAME/report.json under a new name, refresh, then select it under Saved acquisition. Each mapped trigger has a qualified single-pixel energy and one collecting strip on each detector face. Its cell is the intersection of those strips. The spectrum also includes qualified multi-strip energies.

Each face shows the collector’s slow energy and the signed fast signals from its available neighbors. The displayed fast ratio divides the lower-minus-higher reading by the trigger’s single-pixel energy and requires both neighbors. Older receipts can be replayed from the original saved charge libraries and settings to obtain measurements they did not capture.

For nine additional interior strip pairs, a lateral calibration pooled from strips on the same detector face can estimate X or Y. The position inspector identifies the method, the tested energy range and each available axis. These transfer measurements use timing for conditioning and have their own energy support. For qualified triggers with two collecting strips on each face, open the pairing inspector to see both X/Y assignments and the Compton angles permitted by their energies. Multiple photons arriving together can produce this same strip pattern.

To apply the current calibration to an acquisition that already saved neighbor signals, collector timing and channel geometry, write a new report and open it in Control:

The direct position calibration covers X11 or X12 paired with Y07 or Y09 on the matching simulated field. The difference between the two preamplifier 50% constant-fraction crossing times estimates depth. Depth and signed fast neighbor readings supply the lateral estimates. Independent checks used 250, 500 and 662 keV pulses on these four pairs. See What the simulated readout resolves for the threshold, overlap and held-out calibration comparisons; those are separate from the four-acquisition imaging evaluation above.

The trigger inspector also shows an apparent depth for the measured strip intersection. It interpolates the X-minus-Y preamplifier timing difference on that pixel’s simulated 500 keV reference curve. Of 256 pixels, 216 have a usable curve and 16 have an independent off-center check. Timing outside a curve’s sampled range leaves the depth unavailable. Each compatible two-strip pairing shows its own apparent depths. Simultaneous signals from nearby strips can shift those times, so use the energy and order display to inspect alternatives.

To look up a trigger by its original number, expand Inspect any recorded trigger. It shows the X and Y collecting strips, each face’s slow strip sum, guard contacts and recorded quality flags. A trigger without an accepted energy still has its own number.
