2. Set up Windows

Use PowerShell in the project root: the folder containing Control.cmd and Run.cmd. These steps explicitly install or acquire dependencies. Opening the website or Control does not install them.

  1. Install Windows Python and NumPy. Install the official Python install manager from Python.org, then open a new PowerShell window. Install Python 3.13 if it is not already available: 
    py install 3.13
py -3.13 --version
py -3.13 -m pip install numpy
py -3.13 -c "import sys, numpy; print(sys.executable); print('NumPy', numpy.__version__)"
$env:SITE_PYTHON = py -3.13 -c "import sys; print(sys.executable)"

    Checkpoint: Python reports 3.13.x and the import prints a NumPy version. The Python packaging guide explains interpreter-specific pip commands. These commands prepare the Windows Python used by Control, not the WSL Python. For direct Windows HDF5 or GeGI analysis outside the managed transport route, use py -3.13 -m pip install h5py scipy PyYAML in this same interpreter.

  2. Extract the student software. Use the student ZIP above, and keep its extracted folder in its final location. Run the remaining project commands in PowerShell from this folder, containing Control.cmd, Run.cmd and simulation/.
  3. Install Juliaup, then the pinned Julia packages. The official Juliaup Windows command is: 
    winget install --name Julia --id 9NJNWW8PVKMN -e -s msstore

    Open a new PowerShell window in the extracted project folder, then run:

    juliaup add 1.13.0
juliaup override set 1.13.0
julia --version
julia --startup-file=no --project=simulation -e "using Pkg; Pkg.instantiate(); using SolidStateDetectors, JSON, Unitful; Pkg.status()"

    Checkpoint: julia --version reports 1.13.0 and all three package imports succeed. Pkg.instantiate downloads the packages in the supplied manifest; do not install a separate SSD version or edit the Project/Manifest pair. The directory override applies to this project.

  4. Install WSL2 with the named Ubuntu distribution. In an administrator PowerShell window, follow Microsoft's WSL installation and run: 
    wsl --install -d Ubuntu-24.04

    Restart if requested. Open Ubuntu-24.04 once and complete its Linux username/password setup. Back in PowerShell:

    wsl --list --verbose

    Checkpoint: the list contains Ubuntu-24.04 with VERSION 2. If this existing distribution uses version 1, run wsl --set-version Ubuntu-24.04 2. Use the exact distribution name; a different Ubuntu version does not supply this launcher's configured environment.

  5. Install Pixi inside Ubuntu, then the locked transport packages. Open the Ubuntu shell from PowerShell: 
    wsl -d Ubuntu-24.04

    In the Ubuntu shell, run the official Linux Pixi installer, verify it, then return to PowerShell:

    curl -fsSL https://pixi.sh/install.sh | sh
"$HOME/.pixi/bin/pixi" --version
exit

    In PowerShell in the extracted project root, install the locked environment:

    $Project = (Get-Location).Path
wsl.exe -d Ubuntu-24.04 --cd "$Project\transport" -- bash -lc '$HOME/.pixi/bin/pixi install --locked'
.\transport\Run.cmd versions

    Checkpoint: the version check reports remage 1.1.0 and Geant4 11.3.2. Pixi installs Python 3.13, NumPy, SciPy, h5py, PyYAML, Geant4 data and the build tools from transport/pixi.lock into its Linux environment. Do not pip-install these packages into that locked environment. They do not replace Windows Python or its NumPy installation.

  6. Acquire the exact upstream cryostat files. Expand the recipe below. The nine files are fetched locally from the manifest-pinned commit and verified before use.
    Download the nine pinned source files

    The authority is transport/cryostat-source.json: jintonic/geant4, commit 1ff3371e0afb804115773af0541b3e56bd660f8c, directory detector/Ge/cryostat/LBNL. Run this in the project root:

    $m = Get-Content .\transport\cryostat-source.json -Raw | ConvertFrom-Json
$target = Join-Path (Get-Location).Path $m.local_cache
New-Item -ItemType Directory -Force $target | Out-Null
foreach ($f in $m.files) {
    $dest = Join-Path $target $f.name
    if (Test-Path -LiteralPath $dest) {
        if ((Get-FileHash -LiteralPath $dest).Hash.ToLowerInvariant() -ne $f.sha256) { throw "Existing file differs: $($f.name)" }
        continue
    }
    $temp = $dest + '.download'
    if (Test-Path -LiteralPath $temp) { throw "Inspect previous download first: $temp" }
    $url = 'https://raw.githubusercontent.com/' + $m.repository + '/' + $m.commit + '/' + $m.directory + '/' + $f.name
    Invoke-WebRequest -UseBasicParsing -Uri $url -OutFile $temp
    if ((Get-Item -LiteralPath $temp).Length -ne $f.bytes -or (Get-FileHash -LiteralPath $temp).Hash.ToLowerInvariant() -ne $f.sha256) { throw "Downloaded bytes differ: $($f.name)" }
    [IO.File]::Move($temp, $dest)
}

    Matching existing files are preserved. A failed attempt leaves its labelled .download file for inspection. The final files belong directly in .local/transport/LBNL/. They are not republished or relicensed by this project.

  7. Build the source-bound exporter used by Control. 
    $env:SITE_PYTHON = py -3.13 -c "import sys; print(sys.executable)"
.\Run.cmd setup -BuildPortableSourceExporter
.\Run.cmd setup -BuildCatalogSourceExporter
.\Run.cmd setup -BuildAngleSourceExporter
.\Control.cmd

    These explicit builds use the existing locked environment and record the exporter/source bindings. The first preserves the original five-model route; the second builds the shared geometry exporter for the additional compatible models; the third adds angular geometry support. They install or update no packages. In Control, open New simulation → Prerequisites & setup. It checks automatically; choose Recheck prerequisites after completing a missing step. Start simulation checks the selected build, source, runtime and settings before launching. Address any reported missing or changed dependency. Control opens a protected local page on 127.0.0.1.

Setup checkpoint: all three exporter builds complete, then Control opens Simulation Control with New simulation, My runs and Help. Use Prerequisites & setup on New simulation to resolve any missing item, then continue to the first SAP22 run. When opening Control in a new PowerShell window, repeat the $env:SITE_PYTHON = ... and .\Control.cmd lines so it uses the Python you prepared.

The application and source-bound preparation have been verified on the existing Windows/WSL computer. Fresh-machine installation has not been established; student setup feedback will guide further fixes. A failed prerequisite check is not a successful installation.

Select an existing Python or Julia executable

Control uses SITE_PYTHON when set, otherwise an existing ParaView 6.1.1 Python, otherwise an existing PATH Python. To select an already installed interpreter for this PowerShell session:

$env:SITE_PYTHON = 'C:\path\to\installed\python.exe'
.\Control.cmd

Replace the illustrative path with the actual executable. The child workflow uses the pinned Julia runtime; an explicit JULIA_EXE must be valid. Opening Control installs nothing and does not change system PATH.

    Checkpoint: the SDK command prints an installed path, Juliaup is available, and Pixi is 0.81.0 or newer. You do not need to install system Python or Python packages with pip for the default Mac launcher.

  2. Extract the software and run Setup.command. Keep the extracted folder in its final location. In Terminal, change to that folder (replace the example path), then run: 
    cd "/path/to/END2END-Ge-Student"

3. Complete one small run

Open Control.cmd on Windows or Control.command on macOS in the project root. In the English Simulation Control application, use New simulation for Prerequisites & setup and run configuration, My runs to follow progress and inspect results, and Help for this guide and research tools. New runs calculate geometry/source preparation, radiation deposits, the event ledger, fields and charge, independent calibration, readout, and verified results.

First run: SAP22 · Cs-137 · 100 initial decays

Use the configuration from the completed native macOS and preserved Windows result-reader checks: LBNL modular cryostat, SAP22, Cs137 point decay, nominal source anchor, source/capsule angle +30°, 100 initial nuclei, radiation seed 26092631, one Julia thread and unchanged default electronics. Select SAP22 explicitly if a different detector is initially shown. This is a bounded software example; its saved acceptance contained 97 zero-deposit primaries and three accepted groups, while a changed configuration or seed may give different counts.

  1. Open New simulation → Detector simulation, and select the cryostat, SAP22, source and count above. Set the nominal Source position and +30° source angle. Inspect the SAP22 model panel.
  2. Open More settings to set the seed and one Julia thread. Keep the electronics defaults. The application suggests an unused run name; you can change it to sap22-first if that name is unused. Use Export configuration to save the setup.
  3. Click Start simulation. It checks the current configuration before launching and shows any problem that needs attention.
  4. In My runs, choose Open run to follow its pipeline and stage logs.
  5. After completion, choose Open results. Read Overview, then open Events & waveforms, select a nonzero original primary and pulse group, and choose a signal stage to inspect. Data files provides the matching records and event filters.

What completion looks like: the run reaches verified results, and Overview shows its initial, zero-deposit, nonzero and accepted counts. Events & waveforms opens the saved event signals; Data files opens the settings and actual ledgers. For a run named sap22-first, the output folder is .local/runs/sap22-first/. Keep any recorded failures distinct from accepted groups.

After the first run: choose other settings

Use Copy as new run in My runs to start from a saved setup, or configure another supported setup in New simulation. Adjust the detector, cryostat, source, position, angle or count; use More settings for the seed, threads and electronics. Keep the suggested unused name or enter another. Export or load a configuration to keep the setup. Start simulation checks the current selections each time. The model and source coverage describes supported combinations and their acceptance scope.

5. Stop, resume and adjust settings

In My runs, choose Open run, then Stop at next boundary for a decay run. The current stage or batch reaches a verified completed boundary first; Stop is not immediate. When the status is Stopped at stage boundary, Resume saved settings verifies sealed stages and batches, reuses completed work and continues pending work with the same settings. Completed batches remain available through Open results. Keep the launcher open until completion or the stopped boundary. Uncertain unsealed attempts are retained for inspection. The legacy gamma route uses Stop after current stage. See the shared count and recovery contract.

To change detector, source or electronics, use Copy as new run and edit the new setup. It copies the saved selections, including pose, seed and electronics, and suggests a new name. Resume uses the stopped run’s saved settings. The fresh two-source GeGI acquisition has its own Stop and Resume saved acquisition controls, preserving its continuous source and electronics state.

6. Analyze your own results

Open a LBNL detector run from My runs for its settings, receipts and logs, then choose Open results. Overview summarizes the run; Events & waveforms follows its original primary IDs and pulse groups; Data files provides the saved records. A saved nonzero waveform is selected first when available. The Charge, Current, Preamplifier, Shaped signal and All stages views keep the same selected event and pulse group, with signed signals and units.

Each signal has a useful independent focus range; Full saved window restores its saved time span. Where a dense early preamp view is available, it is an explicitly labelled electronics-only replay from full signed charge. It does not recover unsaved original analog samples or alter the original peak, ADC code or reconstructed energy. Collection caps and incomplete endpoints remain visible.

Truth deposited energy, induced charge-equivalent energy and reconstructed energy are separate values. A true zero has no fabricated waveform and keeps reconstructed energy unavailable. Native failures retain their truth and error; unknown response quantities remain null. Changing the next-run form does not relabel the saved result. Selected run source pose and Selected run settings show that run's recorded angle, position, rotation and provenance; earlier runs remain labelled as legacy fixed poses. Stop/Resume uses those saved settings.

Enter the run's original global initial ID and choose Find event; a batch run automatically loads the corresponding batch and nonzero-event page. Use Previous event and Next event to move through the loaded nonzero records. Open Advanced event navigation for the zero-based Saved batch index and Nonzero event offset; use Load saved page, Previous page or Next page to load another page. The offset counts stored nonzero events, not the original primary ID. Initial, zero/nonzero, failed and rejected totals remain in the summary, with the original efficiency denominator. New normalized truth/scalars and analysis JSON/CSV omit zero-input rows and artificial zero waveforms; nonzero failures and rejections stay. Historical raw files remain unchanged. Waveform previews cover only the first 16 groups per batch; other groups retain their saved scalar results and full native signals, with preview unavailability shown explicitly.

Saved energy spectrum · raw counts reads an existing verified histogram. Its label distinguishes the full run from the selected sealed batch; it does not use only the current event page. Truth deposited energy per initial primary and accepted peak-ADC reconstructed energy per pulse remain separate populations. The original initial/zero/nonzero census and underflow/overflow counts remain explicit; this is not an experimental spectrum or physical-resolution claim. Waveform feature and synthetic acquisition panels appear only when their saved export is present, and opening them still verifies their inputs without starting a calculation or export.

7. Troubleshoot a setup or run

  • Setup fails: keep its log and exact error, then check the platform prerequisites and pinned versions above. Opening Control does not install dependencies.
  • Start simulation refuses the setup: inspect the stated compatibility, source pose or missing input, correct it and try again. The configuration is checked before any simulation starts.
  • No energy or waveform: check the initial/nonzero counts, native-failure status, threshold and saved-waveform coverage. An unavailable response is not zero.
  • A run was interrupted: inspect its saved completion state before another launch. Use Resume saved settings at a verified stopped boundary or the specifically supported recovery tools.

For GitHub Issues, include the operating system, software revision, detector/source/count, run name, failing step and exact error.

What the examples establish

The five original Control connectors retain their completed bounded examples. Each of the five added models completed one preselected 500-decay Cs137 case through the public Check, Run and Inspect commands on the existing prepared computer. All 2,500 initial events remain: 2,485 zero-deposit events and 15 pulse groups, comprising nine accepted groups, three below-threshold readout rejections and three KL01 native failures. The KL01 failures keep their original truth and error with unknown charge/readout null; they are not successful charge calculations. Cs137, Am241 and Ba133 share factorized software support across ten configurations; this does not mean thirty actual model/source science acceptances.

These are bounded engineering examples with synthetic electronics and explicit model/geometry limitations. Successful processing does not establish calibrated charge-collection efficiency, experimental agreement, physical energy resolution or numerical convergence.

Source creation/deposition time is not carrier drift time. A readout threshold changes acceptance, not the original primary census. Zeros, endpoint/cap flags, electronics rejects and native failures remain distinct. The GeRC02 Li50min operating variant and KM candidate keep their recorded model and polarity qualifications.

Platform setup and test scope are recorded in the installation sections above. Saved galleries, 10K campaigns and million-decay radiation results are distinct datasets; follow each page's scope and receipts.

Configuration topics

GeGI: source, 34 electrodes and Compton imaging

Rotate the GeGI cryostat and inspect its dimensions · GeGI detector model · Four independent acquisitions: signals and conditional imaging. The public results and your own local runs retain separate input settings and event identities.

  1. Choose the setup. Open New simulation → Detector simulation, select GeGI cryostat and GeGI, then choose its monoenergetic gamma point source. Enter gamma energy from 1 to 10000 keV, source x/y/z in mm and 1–10000 initial gamma primaries. The crystal centre is the origin and +z is the front. This source is isotropic: the denominator counts every emitted gamma, including misses. Start with 100; a small run can have no Ge deposit.
  2. Start the run. Set electronics, a radiation seed and one or two Julia threads in More settings, then choose Start simulation. It checks the setup before executing geometry, transport, event ledger, native charge, independent calibration, readout and reconstruction. Stop waits for a stage boundary; Resume reuses verified completed work with the saved settings. The first installation computes native fields; an exact locally saved GeGI state can be reused. Field data and precomputed examples are not included in the software ZIP.
  3. Follow your event. In My runs, open the completed run and its results. In GeGI multichannel results and Compton imaging, choose an Original nonzero primary ID. Its event journey shows actual signed charge, current, preamp and shaper samples for all 32 strips and two guards, plus the shared waveform-reconstruction status. New standalone runs do not infer depth or create a source map without a compatible independent waveform calibration. Fixed energy readout and original timing diagnostics remain available. Open Selected event identity, filters and original native files and Actual saved stage data for the exact native JSON/CSV, original LH5 transport, ledger, independent electronics calibration, configuration and recorded hashes under .local/runs/NAME/.

The standalone transport workflow launches a monoenergetic gamma source. To generate new Cs-137 and Co-60 decays together, use fresh sources with compact candidate storage. What an acquisition checkpoint preserves

The source checkpoint records the common decay clock, next parent identity and Geant4 random-number state. The candidate database retains future daughter deposits, current pulses, all 34 channel noise-generator states, filter history, unfinished candidate windows, counts and the committed trigger boundary. Resume checks the original configuration and implementation hashes before continuing. Candidate rows and the matching checkpoint commit in one SQLite transaction. The general restart pattern is described by OpenMC batch statepoints; the all-or-nothing database behavior is described in SQLite atomic commit.

The design follows commercial list-mode practice: continuously process signals, record compact measurements and optionally retain pulse traces. XIA describes event headers and optional traces; CAEN separates waveform, list and histogram output. These references explain the storage approach, not GeGI's undocumented internal file sizes or selection rules.
