# SSD CPU quickstart

This is a small, cache-free calculation example, not a replacement for the complete numerical campaign behind the website. It uses the distributed `BEGe_GD32B_reference` model without editing its geometry, contacts, bias, impurity or drift model. The deliberately bounded grid settings belong only to this quickstart.

## Run from a downloaded or cloned repository

Install Julia **1.13.x** and check `julia --version`. No GPU, CUDA driver, Python, ParaView, Docker or Geant4 is required for these commands. The first package installation needs internet access; Julia then caches the packages locally.

From the repository root:

```console
julia --startup-file=no --project=simulation -e "using Pkg; Pkg.instantiate()"
julia --startup-file=no --project=simulation simulation/run.jl --check-models
julia --startup-file=no --threads=2 --project=simulation simulation/run.jl
```

The first command installs the versions in `Manifest.toml`; it does not upgrade them. The second constructs every distributed detector and checks that its configuration and relative includes can be loaded. It does **not** calculate all detector fields. The last command calculates electric and weighting fields on CPU, drifts one synthetic 662 keV charge deposit, and calculates the signal on contact 1.

## Outputs

Everything generated by the example stays in `.local/quickstart/`, ignored by Git:

| File | Meaning |
|---|---|
| `signal.csv` | Time, induced signal in equivalent-energy units, and signed charge fraction |
| `waveform.svg` | A plot of the actual calculated electrode signal; open in a browser |
| `run.json` | Parameters, model/environment hashes, solver iteration checks, carrier endpoints and runtime |

The runner refuses to overwrite an existing output directory. For a deliberate rerun, remove only this generated example directory after saving anything important, or provide `--output PATH`. It never reads the original dissertation field caches or writes into `models/`.

## Interpretation and upgrades

`induced_equivalent_energy_keV` is SSD's electrode signal expressed in energy-equivalent units. It is **not** reconstructed energy from an ADC. The example has no radiation transport, electronics, noise, Fano statistics, diffusion or self-repulsion. The original model's other settings are retained. A numerical tolerance check and a nearly unit final charge are smoke checks, not grid convergence or experimental validation.

The reference is based on published dimensions with documented assumptions; it is not an as-built calibrated detector. Different solver grids can produce a different waveform from the saved website examples. Consult `models/catalog.json` and the model guide before quantitative use.

Keep `Project.toml` and `Manifest.toml` together. For an upgrade, create a branch, change the version constraints intentionally, regenerate the lockfile, run both the all-model construction check and this example, and record waveform/solver differences in `PROGRESS.md`. Never silently change the original YAML files to pass a test. Keep the existing `Additional_Simulations/environment` unchanged until the full campaign is separately migrated.

The commands and source-relative paths are designed for Windows, Linux and macOS; platform claims must be based on actual tests. Installation and validation evidence is recorded in `PROGRESS.md`, not inferred from a successful website build.
