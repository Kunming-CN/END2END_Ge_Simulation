Run and understand GeSignal

Set up Windows, use Control, or inspect the files and identities in a saved run.

Local workflow

  1. Set up Windows — prepare the pinned environment and source files.
  2. Use Control — check a supported setup and run the pipeline.
  3. Read and analyze a saved result — inspect event identities and original files.
  4. Stop and resume saved settings — reuse verified completed work.

Advanced and historical routes cover separate command-line, replay and recovery workflows.

Browse saved results

Choose a saved dataset to find its available waveforms, spectra, radiation views and exact files. The teaching, cryostat gamma, four-case Cs137 10K, two-case million-decay campaigns and GeGI Compton imaging retain separate geometries and event IDs. Use the 17-model detector library for shapes, fields and original model settings, or compare LBNL and GeGI assemblies.

The website displays saved data; it does not start simulations. Seventeen viewable models do not mean seventeen executable Control models.

Browse an offline website copy

Include docs/ in your checkout. From the project root, use an existing Windows Python:

python -m http.server 8765 --bind 127.0.0.1 --directory docs

Open http://127.0.0.1:8765/. Interactive viewers need HTTP to load their saved data; opening HTML directly may show only a static fallback.

Set up Windows

Use PowerShell in the project root: the folder containing Control.cmd and Run.cmd. These steps explicitly install or acquire dependencies. Opening the website or Control does not install them.

  1. Install the platform tools. You need Git, Windows Python 3.10+, Juliaup, WSL2 with Ubuntu-24.04, and Pixi inside Ubuntu. Follow the official Juliaup, WSL and Pixi instructions. WSL may need an administrator and restart. No GPU or ParaView installation is required.
  2. Obtain the software. Students can download the software ZIP and extract it. It includes the Control runtime, canonical detector models, pinned environment files and this guide. Saved results, standalone demonstrations, developer tests, reports and publication tools are excluded. Browse existing results online. Git history and installed dependencies are not included in the ZIP. Developers can instead use a source-only checkout: 
    git clone --filter=blob:none --sparse https://github.com/Kunming-CN/END2END_Ge_Simulation.git
cd END2END_Ge_Simulation
git sparse-checkout set models simulation transport scenarios tools

    To deliberately keep the saved website offline in a Git checkout, use git sparse-checkout add docs. A normal full clone includes the website and repository history; use the student runtime ZIP for the usual student workflow. The full source checkout is for development. Software-only Control shows original model settings and links to the online geometry viewer when a local saved preview is unavailable.

  3. Prepare the pinned Julia environment. 
    juliaup add 1.13.0
juliaup override set 1.13.0
julia --version
julia --startup-file=no --project=simulation -e "using Pkg; Pkg.instantiate()"

    The directory override selects Julia 1.13.0 for this checkout. Keep the supplied Project/Manifest pair unchanged; it pins SSD 0.11.8, JSON 1.9.0 and Unitful 1.29.0.

  4. Install the locked Linux transport environment. 
    $Project = (Get-Location).Path
wsl.exe -d Ubuntu-24.04 --cd "$Project\transport" -- bash -lc '$HOME/.pixi/bin/pixi install --locked'
.\transport\Run.cmd versions

    The version check should report remage 1.1.0 and Geant4 11.3.2. Pixi keeps the large environment in its Linux cache.

  5. Acquire the exact upstream cryostat files. Expand the recipe below. The nine files are fetched locally from the manifest-pinned commit and verified before use.
    Download the nine pinned source files

    The authority is transport/cryostat-source.json: jintonic/geant4, commit 1ff3371e0afb804115773af0541b3e56bd660f8c, directory detector/Ge/cryostat/LBNL. Run this in the project root:

    $m = Get-Content .\transport\cryostat-source.json -Raw | ConvertFrom-Json
$target = Join-Path (Get-Location).Path $m.local_cache
New-Item -ItemType Directory -Force $target | Out-Null
foreach ($f in $m.files) {
    $dest = Join-Path $target $f.name
    if (Test-Path -LiteralPath $dest) {
        if ((Get-FileHash -LiteralPath $dest).Hash.ToLowerInvariant() -ne $f.sha256) { throw "Existing file differs: $($f.name)" }
        continue
    }
    $temp = $dest + '.download'
    if (Test-Path -LiteralPath $temp) { throw "Inspect previous download first: $temp" }
    $url = 'https://raw.githubusercontent.com/' + $m.repository + '/' + $m.commit + '/' + $m.directory + '/' + $f.name
    Invoke-WebRequest -UseBasicParsing -Uri $url -OutFile $temp
    if ((Get-Item -LiteralPath $temp).Length -ne $f.bytes -or (Get-FileHash -LiteralPath $temp).Hash.ToLowerInvariant() -ne $f.sha256) { throw "Downloaded bytes differ: $($f.name)" }
    [IO.File]::Move($temp, $dest)
}

    Matching existing files are preserved. A failed attempt leaves its labelled .download file for inspection. The final files belong directly in .local/transport/LBNL/. They are not republished or relicensed by this project.

  6. Build the source-bound exporter used by Control. 
    .\Run.cmd setup -BuildPortableSourceExporter
.\Run.cmd setup -BuildCatalogSourceExporter
.\Run.cmd setup -BuildAngleSourceExporter
.\Control.cmd

    These explicit builds use the existing locked environment and record the exporter/source bindings. The first preserves the original five-model route; the second builds the shared geometry exporter for the additional compatible models; the third adds angular geometry support. They install or update no packages. In Control, Check environment reports file readiness. Select a setup and use Check plan to verify its current build, source, runtime and settings. Address any missing or changed dependency before running. Control opens a protected local page on 127.0.0.1.

The application and source-bound preparation have been verified on the existing Windows/WSL computer. Fresh-machine installation has not been established; student setup feedback will guide further fixes. A failed prerequisite check is not a successful installation.

Select an existing Python or Julia executable

Control uses SITE_PYTHON when set, otherwise an existing ParaView 6.1.1 Python, otherwise an existing PATH Python. To select an already installed interpreter for this PowerShell session:

$env:SITE_PYTHON = 'C:\path\to\installed\python.exe'
.\Control.cmd

Replace the illustrative path with the actual executable. The child workflow uses the pinned Julia runtime; an explicit JULIA_EXE must be valid. Opening Control installs nothing and does not change system PATH.

Use Control

Double-click Control.cmd in the project root. It opens the English Local simulation application. New runs calculate geometry/source preparation, radiation deposits, the event ledger, fields and charge, independent calibration, readout, and verified results.

Inspect a model, then choose a supported setup

The Detector · all catalog models list lets you select all seventeen models. The model panel shows its original ID, detector type, reference/candidate/scenario qualification, contacts and signed voltages. Its image is a checked saved catalog geometry; Open saved rotatable geometry opens the public website. Inspection starts no calculation and does not establish cryostat compatibility, lithium thickness or charge-collection accuracy.

Compatibility belongs to the selected cryostat: ten configurations use LBNL, and the exact GeGI_3D uses the dedicated GeGI cryostat. A detector selection never changes the cryostat. Needs larger cryostat identifies one of the six models whose dimensions do not fit the supported assemblies. The model panel shows the specific dimensions and preserved temperature, contacts, bias and readout choice. View only keeps unsupported selections browsable. Source, Check plan, Run and configuration export stay disabled for that selection; Load configuration can load an existing supported setup. Imports cannot replace an unsupported model with another detector. A loaded setup still needs Check plan. The saved-run event explorer stays tied to its original run when the next model selection changes.

GeGI: 34 electrodes and Compton imaging

Rotate the GeGI cryostat and inspect its dimensions · GeGI detector model · Saved signals and imaging. The earlier two-position acceptance contained five imaging-accepted events, four ambiguous, from 10,000 initial gammas; it was inconclusive for reliable source separation.

Select GeGI cryostat and GeGI, enter gamma energy (1–10000 keV), source x/y/z in mm and the initial gamma count (1–10000). The crystal centre is the origin and +z is the front. This is an isotropic point source: the denominator counts every emitted gamma, including misses. Start with 100. Check plan, run and stop/resume use the same stage controls as other runs. The first new installation computes native fields; an exact locally saved GeGI state can be reused. Field data and precomputed examples are not included in the software ZIP.

The measured front stack has a 1.6 mm exterior cover, 0.8 mm inner shield and an 8.1 mm crystal-to-exterior-front distance. The missing side/rear dimensions and vacuum-gap split are explicit engineering approximations; both specified aluminium alloys use pure aluminium in this first transport model. The frozen 92.3 K, −879/0 V semiconductor model and its original assumptions are unchanged.

Open a completed run to select its original nonzero event and one of 32 strips or two guards. The charge plot retains signed native charge; current, preamp and shaped voltages use the recorded fixed family wiring. X and Y each measure the same charge and must not be added together as event energy. Failed or rejected nonzero events remain available.

The directional Compton map uses matched strip energies and an independent central-pixel SSD timing-to-depth table. It accepts only two resolved interactions within the configured photopeak window. Ambiguous strip matches, missing depth and incomplete carrier collection are reported; both valid scatter orders share the event weight. The known source position and truth hit coordinates are never used to select an order. This model approximation is not a measured depth or angular-resolution calibration. The map gives direction, not source distance or activity. Hardware DAQ channel mapping is not established by the canonical SSD electrode IDs.

The five added models use the existing portable example’s initial-grid parameters: 0.25 mm minimum and 2 mm maximum, with Float64 arithmetic. The actual mesh and checked numerical settings belong to each run’s receipts; these parameter values do not establish grid convergence or physical validation. The original five computation paths retain their recorded settings.

SAP18 uses the frozen SAP18_ring08_scenario model: 0.8 mm readout contact width, contacts 1: 0 V and 2: −380 V, explicit runtime 77 K instead of stored 78 K, its own fresh fields, and one independent negative 500 keV injection through fixed −1 wiring. Its first and only preselected 500-decay acceptance retained all IDs 0–499, including 485 zero deposits, and accepted 15 pulse groups with no native failure, readout rejection or saturation. This proves bounded engineering integration on the prepared computer; the detector identity remains unresolved and the placement is nominal, with no experimental dimension claim.

GeRC02 inspection shows the frozen Ge30min base model and its saved geometry. Its computation connector uses the separate Li50min operating variant (50 minutes at 553.15 K), explicit runtime 77 K instead of stored 78 K, and fresh fields. These identities must remain distinct.

Two cryostats are available: LBNL modular cryostat and GeGI cryostat. The following LBNL settings apply only to the LBNL assembly. Its unchanged world and explicit detector/source anchors compose with the selected detector and source; a source change does not create a new cryostat template. The shared nominal source anchor is global [0, 37.073, 0.290] mm. Point-decay presets are isotropic and uncollimated. Admitted decay sources offer a Source/capsule angle from −30° to +30°, default zero. The source and capsule move together around global z at x=0, y=1.473 mm, with positive degrees from global +y toward +x; the cryostat, crystal and spacer stay fixed. This is engineering placement, not a measured source survey or experimental efficiency claim. For the monoenergetic gamma beam, enter a positive Gamma energy · keV and choose Source anchor: nominal global [0, 37.073, 0.290] mm or +5 mm global [0, 42.073, 0.290] mm. The fixed global −y beam, 20-primary count, time zero and radiation seed 26092631 remain. Gamma angle is disabled. The original 662 keV/+5 mm preset stays frozen; each new selection records its effective energy and placement separately. These controls do not claim experimental accuracy over every energy.

Check plan resolves the effective source position, capsule axis and rotation through the same shared geometry inputs used by Run. Inspect Checked source pose and Checked next-run configuration before starting. Invalid angles, native overlaps and a source outside its fill are refused before transport. Zero retains the original fixed geometry and configuration shape. A nonzero angle is saved with a versioned pose and anchor hash; it requires new transport and cannot relabel a saved fixed-position run. These geometry/software checks do not establish physical validation at every supported angle.

Current angular status: available through Check and Run. Angular GPS commands use Geant4 double-precision formatting and retain the strict source-position identity check. A new SAP22/Cs137/+30° example with 500 initial nuclei completed radiation, native charge, preamp, analog shaper, peak ADC and reconstructed energy: 493 zero-deposit primaries were retained and all seven pulse groups were accepted, with zero native failures, readout rejections or saturation. The earlier position-formatting failure and its raw data remain separate. This is one low-statistics engineering example, not validation of angular efficiency, every catalog combination, experimental agreement or calibrated charge collection. Zero-angle and legacy gamma runs retain their existing admission.

The maintained scenarios/source-presets.json registry supplies the source label, isotope or particle identity, count unit, source position and time/daughter policy. The ten available model configurations offer Cs137, Am241, Ba133 and Co60 at the nominal anchor. Enter an exact positive initial-nucleus count; Check plan verifies the count and seed capacity and shows serial batches of at most 10,000 nuclei each. Geometry, native fields and independent injection calibration are prepared once for the run. The count includes zero-deposit and failed primaries. Numeric limits do not guarantee practical runtime or storage; 500 nuclei is the default bounded example, and a small sample may contain no Ge pulse. The gamma connector retains its fixed 20-primary count. Co60 admission reuses its completed trial after a saved-data audit of event 475: a retained below-threshold rejection is permitted when its provenance and readout decision pass checks. Native failures, saturation and inconsistent records still fail source acceptance. The original threshold, calibration, models and science are unchanged. Inspect Source identity and acceptance before Check plan. Additional sources require their own acceptance; arbitrary uploaded-source support is unavailable.

Co60 event 475 deposited 50.71048586 keV and produced near-zero signed native charge; its peak was 5.392050797e-11 V, with ADC code 0 and null reconstructed energy. All 640 carrier endpoints reached geometric contacts without a step cap or noncontact stop. The saved electronics decision is consistent with the fixed threshold. This is functional engineering acceptance; same-contact collection and the contact-region charge response remain physical-accuracy limitations.

What the shared-source acceptance checked

Each source used one fixed SAP22 case: 500 initial nuclei, radiation seed 26092631, one Julia thread, +700 V and the frozen model, native, electronics and anchor settings. Am241 retained 491 zero-deposit primaries and accepted 9 groups; Ba133 retained 479 zeros and accepted 21. Both had zero native failures, readout rejections or saturation. A 20-primary smoke check may produce only zero deposits and no signal; 500 primaries are a bounded example, not a convergence or physical-validation claim. These bounded engineering checks do not establish experimental source placement, calibrated CCE or numerical convergence. Am241's native science completed, followed by a saved-data validation correction that preserved the original failed CLI receipt and reran no science. Real Chrome passed Am241/Ba133 selection across all five computation connectors and the view-only execution protections.

The six oversized models remain view only in the LBNL assembly; GeGI requires its dedicated cryostat. Choose one or two Julia threads; CPU stages run serially. A source change invalidates Check plan. A loaded unsupported source is refused without replacing it with another selection.

  3. Click Check plan. Review the effective position/orientation in Checked source pose and the Checked next-run configuration. Changing any selection, including angle, invalidates the check.
  4. Click Run simulation. Follow Pipeline and open the stage logs from Runs.

Read and analyze a saved result

Use Show stages for that run's settings, receipts and logs; use Explore events for its original primary IDs and pulse groups. A saved nonzero waveform is selected first when available. The charge, original-bin current, analog preamp and analog shaper plots retain their signed signals and units.

Each signal has a useful independent focus range; Full saved window restores its saved time span. Where a dense early preamp view is available, it is an explicitly labelled electronics-only replay from full signed charge. It does not recover unsaved original analog samples or alter the original peak, ADC code or reconstructed energy. Collection caps and incomplete endpoints remain visible.

Truth deposited energy, induced charge-equivalent energy and reconstructed energy are separate values. A true zero has no fabricated waveform and keeps reconstructed energy unavailable. Native failures retain their truth and error; unknown response quantities remain null. Changing the next-run form does not relabel the saved result. Selected run source pose and Selected run settings show that run's recorded angle, position, rotation and provenance; earlier runs remain labelled as legacy fixed poses. Stop/Resume uses those saved settings.

For a batch run, select its zero-based Saved batch index and Nonzero event offset, then use Load saved page, Previous page or Next page. Pages load on demand and list only nonzero-deposit events with their original IDs. The offset counts stored nonzero events, not the original primary ID. Initial, zero/nonzero, failed and rejected totals remain in the summary, with the original efficiency denominator. New normalized truth/scalars and analysis JSON/CSV omit zero-input rows and artificial zero waveforms; nonzero failures and rejections stay. Historical raw files remain unchanged. Waveform previews cover only the first 16 groups per batch; other groups retain their saved scalar results and full native signals, with preview unavailability shown explicitly.

Saved energy spectrum · raw counts reads an existing verified histogram. Its label distinguishes the full run from the selected sealed batch; it does not use only the current event page. Truth deposited energy per initial primary and accepted peak-ADC reconstructed energy per pulse remain separate populations. The original initial/zero/nonzero census and underflow/overflow counts remain explicit; this is not an experimental spectrum or physical-resolution claim. Waveform feature and synthetic acquisition panels appear only when their saved export is present, and opening them still verifies their inputs without starting a calculation or export.

Stop and resume saved settings

For a decay run, choose Stop at next boundary in the run card. The current stage or batch reaches a verified completed boundary first; Stop is not immediate. When the status is Stopped at stage boundary, Resume saved settings verifies sealed stages and batches, reuses completed work and continues pending work with the same settings. Completed batches remain available through Explore events. Keep the launcher open until completion or the stopped boundary. Uncertain unsealed attempts are retained for inspection and refused rather than silently rerun. The legacy gamma route uses Stop after current stage. See the shared count and recovery contract.

What the examples establish

The five original Control connectors retain their completed bounded examples. Each of the five added models completed one preselected 500-decay Cs137 case through the public Check, Run and Inspect commands on the existing prepared computer. All 2,500 initial events remain: 2,485 zero-deposit events and 15 pulse groups, comprising nine accepted groups, three below-threshold readout rejections and three KL01 native failures. The KL01 failures keep their original truth and error with unknown charge/readout null; they are not successful charge calculations. Cs137, Am241 and Ba133 share factorized software support across ten configurations; this does not mean thirty actual model/source science acceptances.

These are bounded engineering examples with synthetic electronics and explicit model/geometry limitations. Successful processing does not establish calibrated charge-collection efficiency, experimental agreement, physical energy resolution or numerical convergence.

Source creation/deposition time is not carrier drift time. A readout threshold changes acceptance, not the original primary census. Zeros, endpoint/cap flags, electronics rejects and native failures remain distinct. The GeRC02 Li50min operating variant and KM candidate keep their recorded model and polarity qualifications.

Setup evidence covers the existing Windows/WSL computer; student feedback is the next source of portability evidence. Saved galleries, 10K campaigns and million-decay radiation results are distinct datasets; follow each page's scope and receipts.

Advanced and historical routes

Use these only for their stated inputs and scope. They are separate from the primary Control workflow.

Legacy Run.cmd setup and AK02/SAP22 generic runs

This older command-line route supports AK02 and SAP22, not the ring Control adapters. Its check and -BuildExporter refer to the legacy exporter, not Control's -BuildPortableSourceExporter. Prepare the common dependencies and pinned originals first.

.\Run.cmd check
.\Run.cmd setup -BuildExporter
.\Run.cmd check
.\Run.cmd detectors
.\Run.cmd run -Name ak02-smoke -Detector AK02 -Preset smoke

smoke uses 20 initial decays; demo uses 500. A larger run needs a matching verified pilot. -Detector both creates two serial cases, not two crystals together.

Legacy saved electronics profiles

.\Run.cmd settings
.\Run.cmd settings show -View advanced
.\Run.cmd settings save -SaveName my-electronics

These settings commands belong to the legacy route. See electronics settings for profile syntax and binding.

Legacy run inspection and stage resume 
.\Run.cmd status
.\Run.cmd inspect -Name RUN_NAME
.\Run.cmd open -Name RUN_NAME
.\Run.cmd resume -Name RUN_NAME -DryRun
.\Run.cmd resume -Name RUN_NAME

These commands inspect/open or resume their compatible generic-run records. inspect and resume dry-run read saved state without science; exit 0 means the applicable saved-state checks passed, not that a current runtime is ready. Actual resume is explicit and checks the recorded stages/settings. Generic resume is not interrupted native-group recovery. A source mismatch is a reason to inspect preserved evidence, not edit receipts or repeat completed science.

Replay electronics from compatible saved charge

Requires a complete compatible .local/runs/SOURCE with full signed charge, identities, timing and flags, plus Windows Python and the pinned Julia environment. Model ZIPs, public HTML and display samples are not replay inputs. This route calculates electronics only; it does not run radiation or SSD charge transport.

.\Run.cmd replay-readout -Name SOURCE -ReplayName NEW -Detector AK02 -CheckpointGroups -DryRun -Json
.\Run.cmd replay-readout -Name SOURCE -ReplayName NEW -Detector AK02 -CheckpointGroups -Json
.\Run.cmd replay-readout -Name SOURCE -ReplayName NEW -Detector AK02 -CheckpointGroups -Resume -Json

Use an unused derivative name. Resume keeps the same source, detector and saved profile; no profile override. Output is .local/replays/NEW. See charge reuse and group checkpoints.

Earlier bounded native-charge examples from private inputs

This historical entry needs the checked local Cs137 deposits, prepared geometry and field caches for AK02/SAP22, plus the pinned Julia/SSD environment and Windows Python. Those private inputs are not supplied by a clone or model ZIP. It calculates charge and readout from saved deposits; it does not generate new radiation or fields.

.\Run.cmd native-readout -Name native-example -Detector SAP22 -DryRun
.\Run.cmd native-readout -Name native-example -Detector SAP22 -StopAfterGroups 1
.\Run.cmd native-readout -Name native-example -Resume -DryRun
.\Run.cmd native-readout -Name native-example -Resume

This route's default saved IDs and group checkpoint rules apply only here. On resume, omit Detector/PrimaryIds overrides. StopAfterGroups is an electronics-group boundary after native charge, not an immediate native stop. It selects SITE_PYTHON or the existing ParaView Python; set SITE_PYTHON explicitly for a standalone interpreter. See the bounded native contract.

Inspect or reconcile an interrupted historical receipt

After reopening Control, a previous Gamma job may say verification-required. Open Previous saved jobs and recovery and use Verify saved completion for that job before checking another calculation. This reads saved artifacts and starts no new simulation.

Preserve uncertain output and check actual process identities before another action. Control's Verify existing completion reads completed saved artifacts. Inspect denied launch, Finalize saved results and Continue from verified transport are limited to their specifically verified historical cases; they are not general failed-stage retry controls.
